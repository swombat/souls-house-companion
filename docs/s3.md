This is host evidence, not a completed installation or Linux-v0 receipt.

## Verified 2026-10-16

- Existing authorized Tailscale SSH route, ordinary `danieltenner` user on
  `omarchidell`; no replacement network or root service.
- Kernel `7.0.9-arch2-1`, systemd `260`, ordinary user bus present,
  `Linger=yes` already configured.
- User-manager `XDG_CONFIG_HOME=/home/danieltenner/.config`, matching the
  protected configuration paths; `XDG_CONFIG_DIRS=/etc/xdg`.
- Btrfs `/@` mounted at `/`, `/@home` at `/home`, with separate anonymous
  `st_dev` IDs but a common mountinfo superblock device and filesystem UUID.
  Unprivileged `BTRFS_IOC_FS_INFO`
  on opened directory descriptors for both returns the UUID reported by
  mount discovery. No elevated ioctl capability is necessary on this host.
- Pinned Go 1.27.2 race-instrumented runner test binary executed on the Dell:
  all eight real-user-manager subtests passed, no skips. Stdin, literal argv,
  cwd, exit status, no implicit shell, and double-fork descendants on timeout,
  cancellation and normal main-process exit. No matching transient units
  remained afterward. This does not prove containment of deliberately
  self-escaping programs with full user authority.
- The race-instrumented full filesystem package now passes on the actual
  Btrfs home filesystem, including the opt-in production `LoadSystem` /
  `OpenVerified` fixture: create/append/read, copy/move/rename/quarantine,
  protected inode hardlink and symlink denial, and a real nested-subvolume
  boundary. Fixtures were removed. This is not authenticated remote operation
  or service-lifecycle evidence. There were 46 top-level passes and one skip:
  this host has no directly nested proc mount for that optional metadata test.
- Two CLI uninstall retries with a non-secret `Uninstalled` fixture receipt
  and an already absent unit passed against the actual user manager, preserving
  the unrelated personal fixture. This is not a live device-revocation test.

Two actual-host failures were fixed rather than bypassed: opaque `nsfs`
mount roots previously poisoned the entire table, and Btrfs mountinfo's
superblock device differs from a subvolume's statx device. Btrfs binding now
requires mount ID/root attribute plus opened-fd filesystem UUID, while keeping
the actual root device and `STATX_SUBVOL` checks on subsequent handles.
