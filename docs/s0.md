## Spike boundaries

`internal/policy` intersects local and remote grants, with write implying read
and move requiring write on both volumes. It does not authenticate the remote
policy, maintain revisions, or supervise operations.

`internal/volumes` parses mountinfo against an **injected** device-to-UUID map.
It rejects unknown filesystems, absent/ambiguous UUIDs, cloned UUIDs, duplicate
binds and stacked mounts. Its identity includes UUID, filesystem root and
mountpoint, not reboot-unstable mount IDs. It does not yet resolve UUIDs on a
real machine or bind a checked identity to the fd opened by `linuxfs`.
Both are mandatory before remote access. Mount changes require revalidation;
a retained fd alone is not present-tense authorization.

`internal/linuxfs` is a read-engine spike, not a complete access boundary.
Reads first open an O_PATH descriptor, reject non-regular files, then reopen
that retained inode through trusted `/proc/self/fd`; no untrusted pathname
re-resolution or special-device I/O open occurs. Trusted procfs is a runtime
prerequisite. Read its package limitations before integration. Paths injected as roots by
tests are not a folder-permission model: production roots must be verified
mounted volumes, and all protected-state paths must be supplied.

No CLI installation, credential, user unit, enrollment endpoint, WebSocket
transport, operation dispatcher, search cursor, write tool or exec supervisor
is present. No binary has been installed. No Dell fixture has been read.
Tests in this repository cannot establish these missing acceptance items.
