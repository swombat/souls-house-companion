# S1 read-plane checkpoint

The client now has an HTTPS enrollment/session protocol, rotating private
credential persistence, a Cable control connection and device-authenticated
raw HTTP result upload. This is not an installation or acceptance receipt.
House protocol and endpoints are documented in the paired souls-house PR's
`docs/companion-read-plane.md`.

## Local use

Build with the pinned toolchain; `go build -o bin/companion ./cmd/companion`.
`companion volumes --json` discovers real mount identities and reports denied
ones. Keys identify UUID + filesystem root + mountpoint, not transient mount
IDs; bind mounts are separate grants and may overlap bytes.

Create a private policy JSON:

```json
{"residents":[{"id":"public-resident-id","volumes":[{"volume":"linux-volume:actual-sha256","access":"read"}],"execute":false}]}
```

`companion enroll --url https://house.example --request-id REQUEST
--policy /private/ceiling.json --token-stdin` reads only the explicit enrollment
token from stdin. Never put a token in an argument, shell history or log.
`install --user` writes/enables an ordinary user unit; it does not enable linger
or claim boot persistence. Start it with `systemctl --user start
souls-house-companion.service` only after reviewing the ceiling.
`status --json` excludes credentials. `policy show` and `policy apply --policy
FILE` require the service stopped (exclusive lock); apply is a local authority
act. `pause` stops the unit before changing state, and `resume` starts it.

The unit uses a minimal explicit PATH, not a login shell. State is an owned
0700 directory with a 0600 atomically replaced state file. It must not be
placed in a symlinked final directory. Local execute is not a sandbox:
an execute-granted actor can modify this user's files and policy. S1 does
not expose execute or writes.

## Boundaries

- Mount fd binding checks statx mount ID and major/minor against fresh
  mountinfo. Procfs is checked; mount changes invalidate rather than silently
  rebinding. No fallback when openat2 is missing.
- Current state, unit and executable identities are pinned per request. This
  stops live hardlink/rename aliases, not copies in old backups.
- **Btrfs is deliberately denied** pending real subvolume/snapshot treatment.
  No other filesystem is assumed to solve arbitrary historical secret copies.
- Read and directory results are bounded. Search/list cursors are device-local,
  expiring, single-use and bound to actor, both policies, revision and query.
  Skipped/error scope is not reported as complete.
- Reconnect never replays an operation. A kernel read may not cancel promptly;
  request context and post-I/O local checks suppress result delivery.
- Credential rotation uses a durable pending request and bounded server
  recovery. A copied current credential is still authority until rotated or
  revoked. No automatic revoke on ambiguous network retries is claimed.
- A remote policy narrowing UI/API is follow-up work. Local `policy apply`
  records a distinct safe event before committing the new ceiling.
- Uninstall/device-self-revoke ergonomics, writes, execute and real Dell
  persistence/rollback acceptance remain later stages.

Use safe fixtures only. No personal-file scan, live enrollment, device
credential, service or Dell operation was needed to run the local tests.
